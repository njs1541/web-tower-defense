# R02 조사 보고서: R01 승인 기술안 시제품 결과

- 작성: Claude (Opus 5.5)
- 작성일: 2026-11-23
- 대상 버전: v0.55.23
- 범위: R01에서 승인된 A-01, A-03, A-05, A-06, A-07, A-08, A-11을 `test/`에 시제품으로 만들고 측정한 결과(A-10). 웹 조사는 이번 회차에 하지 않았다.
- 전제: 현재 바디(b00, b01-b09)와 리아나 파츠는 사양 밖 임시본이다(B-01). 아래 수치 중 **크기와 위치에 관한 것은 새 b00이 오면 다시 잰다.** 방식(구조, 구동, 용량 비율)에 관한 결과는 바디가 바뀌어도 그대로 유효하다.
- 표기: **[측정]** 스크립트로 잰 값. **[관찰]** 스크린샷을 눈으로 본 것. **[의견]** Claude의 판단.

---

## 1. 요약

1. **DOM 리그는 동작한다.** 형제 div 23개 + 누적 행렬 + z-index로 21층 겹침 순서(칼이 아래팔 밑으로 가는 경우 포함)를 그대로 재현했다. Canvas와 rAF를 쓰지 않는다.
2. **Web Animations API에서 키프레임 밀도가 결정적이다.** 30fps로 샘플링하면 관절 벌어짐이 최대 3.5px(공격), 나머지 모션은 2px 미만이다. 한 바퀴 6개로 줄이면 공격에서 최대 29.7px이 벌어진다.
3. **용량은 트림과 WebP로 약 95% 줄었다.** 파츠 23장 원본 3,261KB → 트림 PNG 1,108KB → WebP 156KB. 아틀라스로 묶으면 바디 32KB + 리아나 106KB다.
4. **36px 전장 스트립은 알아볼 수 있다.** 72px 프레임, 12fps, 4개 모션 합계 WebP 132KB.
5. **납품 자동 검사가 현재 b00의 규격 위반 5건을 잡는다.** 리아나 파츠는 실패 0건이지만, 자동 검사로 못 잡는 파츠 혼입(바지 파츠에 손·칼자루)이 모션 화면에서 드러났다.

## 3. 결과

### 3.1 DOM 리그 (A-01)

- **[측정]** 정지 자세(관절 0도) 조립 결과를 c00과 비교하면, 조립본 픽셀 중 c00에서 5px 넘게 벗어난 것은 0.03%다. 반대로 c00 중 조립본에 없는 부분은 3.54%인데, 대부분 사양에서 뺀 칼집이다(**[관찰]** 스크린샷 대조).
- **[관찰]** 칼(c13)이 가까운 아래팔(b05) 밑에 그려지면서 팔을 따라 움직인다. 중첩 div로는 만들 수 없는 순서다.
- **[측정]** 페이지 오류 0건.

### 3.2 WAAPI 키프레임 밀도 (A-05 조건)

관절 벌어짐: 자식 뼈의 피벗이 부모 레이어와 자식 레이어에서 각각 어디에 놓이는지의 거리(1024px 캔버스 기준). 정확한 계산이면 0이다. 한 바퀴를 240개 시점으로 나눠 실제 브라우저 계산값을 읽었다.

| 모션 (한 바퀴) | 촘촘히 (30fps) | 성기게 (6개) |
|---|---|---|
| 대기 (5.03초) | 151개, 최대 0.00px | 최대 0.96px |
| 이동 (0.97초) | 29개, 최대 0.23px | 최대 3.57px |
| 공격 (0.77초) | 23개, **최대 3.49px** | **최대 29.7px** |
| 피격 (0.56초) | 17개, 최대 1.81px | 최대 12.9px |

- **[측정]** 가장 크게 벌어지는 곳은 모두 가까운 아래팔(b05) 관절이다. 체인 끝이라 회전이 누적되기 때문이다.
- **[의견]** 공격의 3.49px은 빠른 내려치기 구간(0.23초에 큰 각도 변화)에서 나온다. 로비 화면은 보통 0.4-0.6배로 축소해 보여 주므로 화면상 1-2px이다. 기준을 "30fps 기본, 빠른 구간은 60fps"로 두면 1px 안쪽으로 줄일 수 있다고 본다(미측정).

### 3.3 용량 (A-08, A-11)

| 구분 | 원본 PNG(1024, 녹색 배경) | 트림 PNG | 트림 WebP(품질 0.9) | 아틀라스 WebP |
|---|---|---|---|---|
| 바디 9장 | 428KB | 321KB | 38KB | 32KB (1209×332) |
| 리아나 14장 | 2,833KB | 787KB | 118KB | 106KB (1843×506) |
| 합계 | 3,261KB | 1,108KB | 156KB | 138KB |

- **[측정]** 파츠의 실제 그림 영역은 캔버스의 0.39-9.7%다. 트림이 용량의 약 2/3를 줄이고, WebP가 나머지의 약 86%를 줄였다.
- **[측정]** 무손실 WebP는 헤드리스 Edge에서 인코딩이 너무 느려(23장에 3분 넘게 걸려도 끝나지 않음) 이번 측정에서 뺐다.
- **[측정]** 녹색 번짐 제거(투명 경계 2px 안쪽에서 G를 max(R, B)로 낮춤)로 18,671픽셀을 보정했다.
- **[의견]** 출시 45명 기준 캐릭터 아틀라스 약 106KB × 45 ≈ 4.8MB다. 도감은 선택한 지휘관만 불러오므로(사용자 결정) 첫 로딩에는 들어가지 않는다. 손실 WebP 품질 0.9의 화질은 Gemini와 사용자의 눈 확인이 필요하다.

### 3.4 전장 스트립 (A-03)

| 모션 | 프레임 | 길이 | WebP |
|---|---|---|---|
| 대기 (호흡 1번) | 30 | 2.51초 | 67.6KB |
| 이동 | 12 | 0.97초 | 27.5KB |
| 공격 | 9 | 0.77초 | 21.7KB |
| 피격 | 7 | 0.56초 | 15.3KB |
| 합계 | 58 | | 132KB |

- **[측정]** 모든 모션의 공통 영역은 933px 정사각형이고, 72px 프레임으로 줄였다(약 1/13). 36px 화면에서 캐릭터 키는 약 33px이다.
- **[관찰]** 36px에서 칼 휘두르기, 다리 교차, 방패 위치가 구분된다. 얼굴 표정은 보이지 않는다.
- **[관찰]** 공격 때 칼이 왼쪽으로 크게 나가서 공통 영역이 넓어지고, 그만큼 모든 모션에서 캐릭터가 작아진다.
- **[의견]** 대기 30프레임이 전체 용량의 절반이다. 대기는 36px에서 움직임이 거의 안 보이므로 8fps 이하로 줄여도 된다고 본다. 출시 UR/U 8명이면 스트립 합계 약 1MB다.

### 3.5 납품 자동 검사 (A-07)

**[측정]** 현재 바디 검사 결과(실패 5건):

| 항목 | 측정값 | 사양 |
|---|---|---|
| 머리 꼭대기 y | 110 | 170-190 |
| 발바닥 y | 965 | 870-890 |
| 머리 높이 | 303px (목 y=413) | 260-300 |
| 전체 키 | 856px, 2.83등신 | 680-720, 2.5등신 |
| 몸통 색 | rgb(244,202,182), 피부색 100% | 중간 회색 #8A8F98 |

R01 4.3절의 "머리 약 295px, 약 2.9등신"은 눈대중이었고, 검사 스크립트 값(303px, 2.83등신)으로 바꾼다. 결론(사양 미달)은 같다.

**[측정]** 리아나 파츠: 실패 0건, 경고 11건(외곽 녹색 번짐 10건, 조립 시 c00 4.48% 미포함 1건 = 칼집). c00, c06, c13, c14는 알파 없는 RGB이고 나머지는 RGBA다. 검사는 두 형식을 모두 받는다.

**[관찰] 자동 검사로 못 잡은 결함:** `c11_pants_near`(가까운 다리 의상)에 손가락, 칼자루 끝, 튜닉 밑단 일부가 함께 들어 있다. 정지 자세에서는 c00과 일치하므로 검사를 통과하지만, 공격·이동 모션에서 팔이 움직이면 그 조각이 원래 자리에 남는다. 사양 2절 "파츠에는 해당 부위만 그린다"를 어긴 것이다. 이런 혼입은 `rig_dom.html`에서 모션을 돌려 눈으로 확인하는 절차로 잡는다.

## 4. 확인하지 못한 것

- 실제 게임 화면(로비, 도감)에 넣었을 때의 성능. 시제품은 독립 페이지다.
- 리그를 여러 개 동시에 띄울 때의 비용(도감은 1명만 재생하므로 우선순위 낮음).
- 손실 WebP 0.9의 화질에 대한 사람의 판단.
- 공격 60fps 키프레임의 실제 벌어짐 값.
- A-04 흔들림(앞머리·치마 미세 회전)은 아직 모션에 넣지 않았다.

## 5. 다시 만드는 방법

