## 1. 요약

1. **사양 v2와 가이드를 만들었다.** `test/ASSET_SPEC.md`를 따로 그리기 방식으로 다시 썼고(옛 사양은 `ASSET_SPEC_v1.md`), 기준선·관절 가이드 이미지와 종족 뼈대 파일을 만들었다.
2. **관절 벌어짐을 1px 안으로 줄였다.** 각도 변화가 빠른 구간에 키프레임을 더 넣어 공격 동작 최대 3.49px → 0.24px.
3. **전장 스트립의 숨은 결함 두 개를 고쳤다.** 칼끝이 1024 캔버스 밖으로 나가 잘리던 것과, 좌우 반전 시 몸이 옆으로 튀던 것이다.

5. **도감에 리아나 대기 모션을 붙였다.** 임시본이다(A-17 사용자 의견). 게임 진행에는 영향이 없다.

### 2.2 빌드·굽기 보완 (v0.55.30, A-14, A-15, A-24 ②③)

| 항목 | 전 | 후 |
|---|---|---|
| 관절 벌어짐 최대(공격 / 피격 / 이동) | 3.49 / 1.81 / 0.23px | **0.24 / 0.12 / 0.08px** (키 24→57, 18→27, 30→47) |
| 전장 프레임 | 72×72 정사각형, 중심 = 내용 가운데 | **92×72 직사각형, 중심 = 골반 피벗**(좌우 반전해도 제자리) |
| 전장 fps | 전부 12 | 대기 8, 동작 12 |
| 전장 스트립 합계 | 132KB | **106KB** |
| 투명화 | 0/255 이진 | 소프트 알파(경계 2px, 42,083픽셀) |
| 아틀라스 WebP | 138KB | 206KB (반투명 가장자리 때문에 증가) |

- **[관찰] 기존 스트립은 공격 때 칼끝이 잘려 있었다.** 칼끝이 1024 캔버스 밖(x = -108)까지 나가는데 화면 밖은 캡처되지 않았다. 굽기 화면에 256px 여백을 두어 고쳤다.
- **[관찰] 칼 계단 현상의 진짜 원인은 원본 파츠다.** 소프트 알파를 적용해도 칼 테두리 계단은 남았다. 원본 `c13`을 확대하면 칼 자체가 계단 모양으로 깨져 있고, c00의 칼은 매끈하다. 잘라내기 과정에서 손상된 것이므로 따로 그리기(A-19)로만 해결된다. R02 4.2절의 Gemini 분석(원인은 이진 투명화)을 보완한다.

### 2.3 자리 맞춤 도구 (v0.55.31, A-21, A-06 변경, A-24 ①)

**흐름**

| 단계 | 도구 | 하는 일 |
|---|---|---|
| 1 | `prepare_fit.mjs` | 시트를 소프트 알파로 투명화 → 연결 덩어리로 분리(15px 안 조각은 묶고, 작은 부스러기는 붙이거나 버림) → 슬롯 이름 → 자동 맞춤 → `fit_auto.json` |
| 2 | `fit_tool.html` | 사람이 슬롯 이름, 위치, 회전, 크기, 겹침 순서를 고친다. 점수 0.4 미만은 빨간색 |
| 3 | `export_rig_v2.mjs` | 파츠를 정지 자세 좌표로 미리 구워 아틀라스와 `rig.json`(td-rig-char/2)으로 낸다. 회전 15도 초과는 경고 |
| 4 | `verify_rig.mjs --rig`, `bake_strips.mjs --rig` | 정합, 관절, 전장 스트립 |

**[측정] 가짜 v2 납품 시험**

시험 데이터는 리아나 파츠를 몸·옷 일체형 17슬롯으로 합친 뒤, ±12도 회전과 0.85-1.2배 크기로 시트 4장에 흩은 것이다.

| 항목 | 결과 |
|---|---|
| 슬롯 이름 | **17/17 일치** (시트 안 읽는 순서 규칙) |
| 위치 | 12/17이 6px·2도·0.03 이내. 대부분 1px 안팎 |
| 빗나간 것 | 머리 소체(115px, c00에서 머리카락에 가려짐), 먼 아래팔(130px, 방패에 가려짐), 가까운 아래팔(46px), 칼(10px), 뒷자락(회전 2.7도) |
| 경고 표시 | 머리 소체와 먼 아래팔에 "일치 낮음"(점수 0.4 미만)이 붙었다 |
| 정답 배치 내보내기 | **c00 대비 5px 밖 0.03%(v1과 같음), 관절 벌어짐 0.24px.** 분리 → 맞춤 → 굽기 → 런타임이 정확하다 |
| 자동 맞춤 결과 내보내기 | 5px 밖 0.34%. 머리 소체가 가슴 위로 내려와 덮는 등 눈에 띄는 오류가 있어 사람 조정이 꼭 필요하다 |
| 시간 | 17개에 약 70초 |

- **[의견]** 슬롯 이름을 위치로 정하는 방식은 실패했다. 머리 소체, 앞머리, 뒷머리, 표정은 같은 자리에 겹쳐 모양으로 구분할 수 없었다. 그래서 **"시트 안에서 5절 표 순서대로, 읽는 순서로 놓는다"** 규칙을 사양 2.2절에 넣었다. 이 규칙이 승인이 필요한 사양 변경이다(R03 A-26).
- **[의견]** 무늬 없는 피부나 천은 어디에 놓아도 색이 맞아 자동 맞춤이 약하다. 어두운 선에 가중치를 주고, 표정은 기본 표정에 맞춘 뒤 나머지를 그 패치에 맞추는 방식으로 보완했다. c00에서 가려진 파츠는 Gemini 예상(R02 5.2)대로 자동으로는 어렵다.

### 2.4 게임 연동 (v0.55.32, A-17)

- 런타임을 `js/rig_runtime.js`로 옮겼다. 게임과 시험 화면이 이 파일 하나를 같이 쓴다.
- `CHARACTER_DATA.char_liana.rig`가 있으면 도감 일러스트 창에 "대기 모션" 탭을 맨 앞에 두고 **기본으로 연다**. 그 지휘관 리그만 그때 불러온다.
- 자산은 `publish_rig.mjs`로 `assets/rig/`에 냈다(리아나 v1 임시본 212KB). 정식 v2가 오면 같은 경로로 다시 내보내면 된다.
- **[측정]** 실제 `index.html`(Edge 헤드리스)에서 확인한 것
  - 탭 2개가 나오고 레이어 23개가 재생된다.
  - 탭을 바꾸거나 창을 닫으면 레이어와 애니메이션이 0이 된다.
  - 리그가 없는 지휘관은 기존 그대로다.
  - `startGame()` 후 1라운드가 정상이다. 페이지 오류는 0이다.
- **[관찰] 첫 시험에서 창이 빈 칸으로 보였다.** 창이 뜨기 전에 축소 비율을 계산해 0이 되었기 때문이다. 불러온 뒤 계산하도록 고쳤다.
- UR/U 전장 스트립 교체는 UR/U 파츠가 없어 하지 않았다.

- 자리 맞춤 도구의 사람 조정 화면은 헤드리스에서 열리는 것만 확인했다. 실제로 끌어서 조정하는 사용성은 확인하지 못했다.
