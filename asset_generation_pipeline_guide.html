3. 단계별 빈출 문제점 및 해결 솔루션 (Troubleshooting Bible)

실제 파이프라인 운용 중 발생했던 중대 결함과 현장 해결 조치 기록

ISSUE 01

AI가 시트 박스 안에 텍스트 라벨("1. Skirt", "Main Weapon")을 직접 그려넣는 결함

• 발생 현상: AI에게 설정 시트를 지시하면 각 파츠 박스 상단에 영문 설명 텍스트를 인쇄함. 슬라이서가 해당 영역을 자를 때 글자가 파츠에 잘려 붙어 리깅 화면에서 캐릭터 몸 위에 'Skirt' 글자가 둥둥 떠다님.
• 근본 원인: AI 학습 데이터셋의 설정 시트(Concept Art Sheet)에 텍스트 주석이 많아 이를 필수 구성 요소로 오인함.
• 해결 솔루션:
1) 프롬프트에 [CRITICAL: ZERO TEXT, ABSOLUTELY NO LETTERS, NO WORDS, NO LABELS INSIDE BOXES]를 대문자로 최상단 강조.
2) 템플릿의 박스 헤더 영역(38px 높이)을 슬라이스 좌표에서 영구 제외하는 Safe Margin Padding 도입.
ISSUE 02

크로마키 배경과 캐릭터 복장 색상이 겹쳐 투명 구멍(Hole)이 뚫리는 결함

• 발생 현상: 숲의 종족 실바나의 에메랄드 나뭇잎 드레스와 뾰족한 엘프 귀가 표준 그린 스크린(#00FF00)과 함께 투명화되어 캐릭터 몸에 벌집 구멍이 뚫림.
• 근본 원인: RGB 색차 기반 투명화 시 의상의 그린 채널 값이 크로마키 임계값(Threshold)에 걸려 지워짐.
• 해결 솔루션:
1) 종족별 동적 크로마키 시스템 구축: 숲의 종족은 무조건 마젠타(#FF00FF) 배경으로 강제 생성.
2) 스튜디오 슬라이서에 RGB 거리 기반 디스필(Despill) 가중치 필터를 탑재하여 녹색/자홍색 반사광을 부드럽게 복원.
ISSUE 03

AI가 시트의 박스 크기와 화면 비율을 제멋대로 왜곡하는 문제

• 발생 현상: 턴어라운드 박스를 너무 넓게 그리거나 파츠 박스를 작게 몰아 그려서, 고정 좌표 슬라이싱 시 파츠의 절반이 잘려나감.
• 근본 원인: 텍스트 프롬프트만으로는 2048×1152 캔버스 내에서의 픽셀 그리드 배치를 정확히 인지하지 못함.
• 해결 솔루션:
1) 공식 규격 틀(Template PNG) 강제 첨부: 01~15번 구획선과 번호가 인쇄된 투명 PNG를 생성 도구(나노바나나 등)에 이미지-to-이미지 제2 레퍼런스로 동시 첨부.
2) 스마트 바운딩 박스 오토 트림: AI가 살짝 어긋나게 그리더라도 알파 픽셀의 외곽선을 자동 추적하여 완벽한 크롭 보정.
ISSUE 04

치마와 다리의 3D 클리핑(관통) 및 걷기 애니메이션 불가 문제

• 발생 현상: 치마를 한 덩어리로 잘라 입히면 다리가 앞으로 나올 때 치마 앞면을 뚫고 튀어나오며, 치마 뒷면이 없어 다리 사이가 텅 비어 보임.
• 근본 원인: 2D 평면 레이어 순서상 소체(다리)가 치마보다 앞에 있으면 치마 전체가 가려지고, 뒤에 있으면 치마가 다리를 100% 덮어버림.
• 해결 솔루션:
1) 11번 앞치마(Front) & 15번 뒷치마(Back) 물리적 분리 생성.
2) 3D 샌드위치 Z-Index 결합: 뒷치마(Z:1.8) ➔ 소체 다리(Z:3.0) ➔ 앞치마(Z:4.0) 구조를 적용하여 소체 다리가 치마 안쪽 통에 쏙 들어간 완벽한 3D 입체감 달성.
ISSUE 05

Live2D 눈 깜빡임 시 캐릭터 얼굴이 찌그러지는 미모 훼손 결함

• 발생 현상: 눈을 감길 때 얼굴 부위를 세로로 스쿼시(압축)하면 코와 입, 턱선, 귀까지 함께 눌려 호러 영화 같은 얼굴 왜곡이 일어남.
• 근본 원인: 얼굴 전체 텍스처를 단일 메쉬로 취급하여 변형을 가했기 때문.
• 해결 솔루션:
얼굴 베이스와 턱선은 완전히 고정(Fixed)하고, 오버레이 속눈썹(Eye Lash) 라인만 0.15초간 살짝 내려앉았다 올라오는 '독립 속눈썹 라인 드로우' 기법을 적용하여 원화 고유의 수려한 미모를 100% 보존.

4. 열람 대상별 실무 체크포인트 & 협업 가이드

AI, 그래픽 디자이너, 총괄 디렉터 각 주체별 역할과 확인 사항

🤖

AI 프로그램 (Gemini, ChatGPT, Grok)

  • 단일창 복사 최적화: 나노바나나 등 단일 프롬프트 입력창을 위해 포지티브와 네거티브, 전신 보장 수식어를 결합한 All-in-One 스트링 산출.
  • 텍스트 금지 트리거: 시트 프롬프트에 no text, no letters, no labels를 필수 가드레일로 자동 주입할 것.
  • 크로마키 자동 판별: 캐릭터 설명에 '나무, 잎, 에메랄드, 그린, 자연'이 포함되면 자동으로 마젠타(#FF00FF) 크로마키 프롬프트로 스위칭할 것.
  • 해부학 비율 엄수: 8등신 원화는 7.0~8.0등신, SD 시트는 2.8~3.0등신 키워드를 명확히 분리하여 혼합 프롬프트 방지.
🎨

현업 2D 그래픽 디자이너 (원화가 / 스파인 리거)

  • AI 생성물은 '1차 베이스 소스': AI가 생성한 파츠를 그대로 쓰기보다, 스튜디오 슬라이스 후 클립스튜디오/포토샵에서 엣지 안티앨리어싱 정리 및 관절 피벗(Pivot) 리터칭 진행 권장.
  • 뒷치마와 소체의 관절 블리딩: 다리를 크게 벌리는 모션 시 소체 허벅지 밑바탕이 드러나므로, 소체 04번 박스에 속옷/언더웨어가 깨끗이 채워져 있는지 검수.
  • 좌우 대칭 파츠 효율화: 날개나 견갑 등 좌우 대칭인 파츠는 1쪽만 생성하여 mirrorWings: true로 뒤집어 쓰는 것이 용량/해상도상 유리.
  • 표정 파츠의 크기 일관성: 05~08번 표정 박스의 눈/입 위치가 소체 얼굴과 1:1 오버레이될 수 있도록 얼굴 윤곽선 비율 확인.
👤

총괄 디렉터 / 개발자 (Project Director)

  • 리소스 단가 및 일정 단축: 기존 외주/원화 제작 기간 대비 캐릭터 1인당 제작 시간을 90% 이상 단축하여 주당 5~10인의 지휘관 업데이트 파이프라인 확보.
  • 품질 검수(QC) 5대 필수 항목:
    1. 전신 발끝 잘림 없음?
    2. 텍스트 라벨 침범 없음?
    3. 앞/뒷치마 분리 완료?
    4. 소체 관절 결손 없음?
    5. constants.js 데이터베이스 정상 등록?
  • 지적재산권(IP) 안전성: 독창적인 5대 종족 기획과 고유 세계관 복식 규정을 기반으로 프롬프트를 통제하여 타 게임 저작권 침해 방지.

5. AI 전문가 관점의 추가 제언 (AI Specialist Insights & Future Roadmap)

엔지니어링 시각에서 바라본 차기 파이프라인 고도화 및 품질 혁신 제안 5선

제언 1 • 자동화 & 재현성 극대화

ComfyUI 기반 ControlNet OpenPose + IP-Adapter 로컬 완전 고정 워크플로우 도입

현재 웹 기반 LLM/나노바나나를 활용한 생성 방식은 신속한 아이디어 스케치에는 탁월하나, 매 생성 시 미세한 시드(Seed) 편차와 비결정적(Non-deterministic) 오차가 존재합니다.
차기 단계 제언: 로컬 환경에 ComfyUI를 구축하고, 2048×1152 템플릿의 박스 좌표를 ControlNet Tile/Canny로 하드 픽스(Hard Fix)한 뒤 IP-Adapter를 통해 8등신 원화의 얼굴/의상 특징을 100% 주입하는 '1-Click 시트 자동 생성 노드'로 전환할 것을 제안합니다. 이렇게 하면 텍스트 오염 및 비율 왜곡이 기술적으로 0%가 됩니다.

제언 2 • 전문 툴킷 연동성

웹 캔버스 슬라이서에서 'Spine 2D / Live2D Cubism 호환 멀티레이어 PSD 자동 익스포트' 구축

현재는 슬라이스된 파츠들을 각각의 PNG 파일로 내려받아 캔버스에서 조립하고 있습니다.
차기 단계 제언: sd_asset_studio.html에 ag-psd 라이브러리를 결합하여, 피벗 포인트(Pivot)와 Z-Index 레이어 순서, 마스크가 온전히 보존된 포토샵 PSD 파일로 즉시 묶어서 내보내는(Export PSD) 기능을 탑재할 것을 권장합니다. 현업 원화가나 스파인 리거가 해당 PSD를 열어 10분 만에 뼈대(Bone)를 심고 메쉬를 생성할 수 있어 외주 협업 속도가 비약적으로 향상됩니다.

제언 3 • 비주얼 퀄리티 혁신

딥러닝 기반 Alpha Matting (BiRefNet / RMBG-2.0) 도입을 통한 반투명 베일 및 헤어 엣지 보존

단색 크로마키(Green/Magenta) 키잉은 단단한 외곽선 추출에는 효율적이지만, UR/U 등급 지휘관의 핵심 매력 요소인 '반투명 실크 베일', '미세한 머리카락 가닥', '스타킹 시스루'의 알파 블렌딩에서 녹색/자홍색 색 번짐(Color Bleed)이 미세하게 남는 한계가 있습니다.
차기 단계 제언: 단순 색차 투명화 대신 최신 딥러닝 알파 매팅 모델(BiRefNet 또는 RMBG-2.0)을 파이프라인 중간 단계에 배치하여, 머리카락 한 올과 반투명 쉬폰 레이어까지 100% 투명 알파 채널로 살려내는 울트라 하이엔드 퀄리티 컷아웃을 구현할 것을 제안합니다.

제언 4 • 캐릭터 연속성 보장

캐릭터 고유 LoRA(Low-Rank Adaptation) 또는 FaceID 임베딩을 통한 원화-SD 일체화

한 캐릭터의 8등신 원화와 SD 시트, 차후 추가될 '스킨(Costume)'이나 '전투 이펙트 컷인' 간에 동일 인물이라는 인상을 100% 유지하는 것이 서브컬처 팬덤의 핵심입니다.
차기 단계 제언: 대표 원화 1장이 확정되면 해당 캐릭터의 페이스/헤어 특징을 10초 만에 추출하는 InstantID / FaceID 모델을 파이프라인에 결합하여, 표정 바리에이션이나 추가 포즈를 생성할 때 작화 붕괴 없이 동일 지휘관의 외모를 영구 유지하도록 제안합니다.

제언 5 • 실무 협업 모델 정립

'AI = 초고속 파츠 소스 공장' + '전문 디자이너 = 피벗/물리 메쉬 마스터' 하이브리드 프로덕션

AI로 모든 것을 끝내려 하기보다, "AI는 11종의 초고해상도 원화 소스를 단 3분 만에 공급하고, 전문 디자이너는 관절 피벗 설정과 가슴/머리카락 흔들림 물리 연산(Physics)에만 집중"하는 역할 분담 체계를 정립해야 합니다.
이 하이브리드 모델이 확립되면 소규모 인디 팀이라도 대형 게임사(원신, 승리의 여신 니케 등)급의 압도적인 2D Live2D 퀄리티와 물량을 동시에 달성할 수 있습니다.

6. 내부/외부 실무자 회의용 핵심 안건 5선 (Discussion Topics)

본 문서를 토대로 유관 부서 및 협업 파트너와 결정해야 할 주요 아젠다

안건 1. 공식 시트 템플릿의 파츠 슬롯 확장 여부:
현재 11~15번(상의, 앞치마, 뒷치마, 무기) 체제에서 '신발/부츠 분리 슬롯'과 '망토 독립 슬롯'을 추가로 16~18번으로 확장할 것인지 여부 결정.
안건 2. 크로마키 배경 vs 투명 PNG 직접 출력 방식의 품질 비교 평가:
최신 모델(Flux, SDXL 투명 로라 등)의 네이티브 알파 투명화 품질과 현재의 크로마키 알파 키잉 방식 중 어느 쪽이 프로덕션 라인에 더 안정적인지 실증 비교.
안건 3. Live2D 메쉬 물리 흔들림(바운스) 파라미터 표준화:
